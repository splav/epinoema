# Epinoema: запись и разбор входящих

Epinoema — база идей пользователя. Главное правило: записать мысль должно быть
быстрее, чем решить, куда её положить. Поэтому запись — без вопросов, а
структура появляется потом, при разборе, и только с согласия пользователя.

Все инструменты — из MCP-сервера `epinoema`. Каждая правка сохраняется
в истории с пометкой, что её сделал агент, и может быть откачена.

## Записать

Пользователь говорит «запиши», «запомни», «идея: …» → сразу `add_note`.

- `body` — его слова как есть. Не переписывай, не сокращай, не дополняй
  своими мыслями. Можно убрать служебное «запиши, что…».
- Ничего не спрашивай перед записью. Заполняй `title`, `kind`, `project`,
  `tags` только если пользователь сам их назвал.
- `importance` — только если пользователь прямо сказал о важности.
- Ответ — одна строка: что записано и короткий id (первые 8 символов).

## Разобрать входящие

1. `list_inbox`. Если пусто — так и скажи, одной строкой.
2. Для каждой заметки:
   - если сниппет обрезан — `get_note`;
   - 1–3 вызова `search` по ключевым словам заметки, чтобы найти связанные
     заметки и уже использованные теги и проекты.
3. Покажи предложения одной таблицей, по строке на заметку:

   | id | заметка | тип | теги | проект | связи | статус |

   - **тип**: `idea` — мысль, которую можно развивать; `decision` — принятое
     решение; `meeting` — заметка со встречи; `project` — описание проекта;
     `note` — всё остальное.
   - **теги и проект**: переиспользуй найденные в search. Новый тег — только
     если подходящего нет; строчными буквами, одно-два слова.
   - **связи**: `related` — про одно и то же; `derived_from` — новая выросла из
     старой; `supersedes` — новая заменяет старую. Только если связь очевидна.
   - **статус**: `active`, если пользователь, судя по тексту, будет этим
     заниматься; `parked` — отложенная идея. Не предлагай `done` и `dropped`.
   - **заголовок**: предложи, только если его нет, а текст длиннее одной строки.
4. Дождись ответа. «Да», «ок» — применить всё; правки по строкам — применить
   с ними; «пропусти» — оставить заметку во входящих.
5. Применяй: `update_meta` (всегда со статусом, чтобы заметка ушла из входящих),
   затем `link`. В конце — одна строка: сколько разобрано, сколько осталось.

Больше 15 заметок — разбирай порциями по 10–15, начиная с новых.

## Сроки и диаграмма Ганта

- Даты (`start_on`, `due_on`, формат YYYY-MM-DD) ставь только те, что назвал
  пользователь. «К пятнице» — переведи в дату и назови её в ответе.
- «B после A», «B ждёт A», «сначала A, потом B» → `link(src=B, dst=A, kind="depends_on")`.
  Зависимость направлена от того, кто ждёт, к тому, кого ждут.
- «Покажи план/гант по проекту X» → `gantt(project="X")`; покажи `mermaid` блоком
  ```mermaid и перечисли предупреждения (сорванные сроки) словами.
- Задачи без дат и без зависимостей на диаграмму не попадают — если пользователь
  ждал их там, скажи, каких дат не хватает.

## Никогда без явной просьбы

- Не меняй текст заметки. `update_meta` его и не меняет — не пытайся обойти
  это через add_note с исправленной копией.
- Не ставь и не меняй `importance`.
- Не переводи заметки в `done` или `dropped`.
- Не переименовывай проекты (`rename_project`).
- Не меняй заголовок, который уже есть.

## Найти

«Найди заметку про …» → `search`. Запрос — 1–4 ключевых слова, а не вопрос
целиком; поиск учитывает русские словоформы и опечатки в заголовках.
Поддерживаются `"точная фраза"`, `OR` и `-исключение`. Покажи до 5 результатов:
id, заголовок или начало текста, статус. Ничего не нашлось — попробуй
синонимы один раз, потом скажи, что не нашёл.

## Еженедельное ревью

«Давай ревью», «что я забросил» → `run_report(name="review")`. Три секции:
входящие, важные идеи без движения больше двух недель, изменённое за неделю.

1. Входящие не пусты — сначала разбери их (раздел выше).
2. По каждой забытой важной идее спроси одно: продолжаем (`active`),
   откладываем (`parked`), закрываем (`done` или `dropped`). Меняй статус
   только по ответу.
3. Изменённое за неделю покажи списком, без вопросов, если пользователь
   сам не захочет что-то обсудить.

## Отчёты

- «Всё по проекту X» → `run_report(name="all", project="X")`.
- «Переименуй проект X в Y» → проверь имена через `list_projects`, назови, сколько
  заметок затронет и сольётся ли X с уже существующим Y, дождись «да», потом
  `rename_project`.
- Встроенные: `review`, `inbox`, `stale`, `week`, `all`; свои — `list_reports`.
- Разовый вопрос («сколько идей по месяцам», «что я менял вчера») → `query`
  с одним SELECT. Сначала короткий запрос, потом уточняй; не тяни `body`
  целиком, если хватит `title` и `left(body, 100)`.
- Пользователь хочет запускать отчёт сам → `save_report`, затем скажи ему
  команду: `epi report NAME`. Без просьбы не сохраняй.
